Root Cause Groups:


• 13/17 failures — ptp-operator never deployed to cluster (bc suite, all 13 bc-serial tests)

The telco5g-ptp-tests step wiped and re-created the openshift-ptp namespace, launched a privileged podman pod to build ptp-operator, linuxptp-daemon, and cloud-event-proxy from their upstream main branches, but the build log is truncated at line 496 (mid-template-substitution). • 2/17 failures — DPLL holdover not maintained on T-GM node cnfdf32 (tgm suite)

Test 1: GNSS coldboot never pushes DPLL out of DPLL_LOCKED; ClockClass stays at 6, never reaches 7. Test 2: DPLL does briefly enter holdover (ClockClass 7) but immediately exits to FREERUN/ClockClass 248 because linuxptp-daemon/pkg/dpll/dpll.go:658 maps !d.inSpec directly to PTP_FREERUN, bypassing sustained holdover. An explicit TODO at line 656 acknowledges this gap. Upstream sync commit fd6ff1e (PR #617, 2026-06-30) and/or cloud-event-proxy commit 4b49778 ("fix CurrentState aggregation", merged 2026-07-06 ~1.5h before the job) are the prime suspects.


• 1/17 failure — phc2sys HA failover silent within 60 s (dualnicbcha suite)

After ens2f1 was brought down, no selecting as out-of-domain source clock log line appeared within the 60-second context deadline. The stream was readable (initial match succeeded), so this is a behavioral regression or a tight timeout. The release-4.22 linuxptp-daemon image (same upstream sync commit fd6ff1e) is the runtime under test.


• 1/17 failure — Prometheus unreachable during CPU utilization soak test (dualnicbcha suite)

An infrastructure-level failure independent of code changes; Prometheus was not accessible on the test cluster at that point in the run.
