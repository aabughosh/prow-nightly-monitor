
• Root Cause: The build_images function deleted and recreated the openshift-ptp namespace, then attempted to copy the pull-secret from openshift-config using oc apply. Because oc apply was piped through oc get ... | oc apply, and the secret apparently survived namespace deletion or was pre-existing, the apply hit AlreadyExists and exited with code 1. With set -o errexit active, this immediately terminated the script before any PTP operator was deployed or any test ran.
• Breaking PR/Commit: Unknown — this is a transient infrastructure/cluster state issue, not a code regression. No commits in the provided git log are relevant.
• Flake? yes — this is a race/stale-state condition in namespace teardown; the namespace deletion may not have fully propagated before the secret was re-applied, or a prior run left residual state.
• Fix: Change oc apply to oc apply --dry-run=client first, or use oc delete secret pull-secret --ignore-not-found before the apply step. Alternatively, use kubectl create ... --dry-run=client -o yaml | oc apply -f - pattern to be idempotent.
