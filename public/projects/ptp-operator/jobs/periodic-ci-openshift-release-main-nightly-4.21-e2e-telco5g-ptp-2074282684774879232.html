• 12/24 failures — linuxptp-daemon log stream unreachable (ClockSync GetProfileLogID/GetClockIDForeign timeout): All ClockSync tests in bc (3), dualfollower (3), dualnicbc (3), dualnicbcha (2), and oc-serial test 1 (1) hit could not find regex in log stream … error reading from stream: context deadline exceeded or timedout waiting for matches. • Root Cause: The test helper GetProfileLogID in test/pkg/ptphelper/ptphelper.go opens a live Kubernetes log stream (Follow: true, no TailLines) via pods.GetPodLogsRegex searching for the regex (?m).?Ptp4lConf: #profile: (.|\n)?message_tag \[([^\]]*)\] within a 3-minute timeout. The stream — opened with context.TODO() so no test-side deadline — is being terminated by the infrastructure with context deadline exceeded before the regex can be matched. This error pattern repeats identically across all ClockSync tests in bc, dualfollower, dualnicbc, and dualnicbcha suites, confirming a cluster-wide log streaming connectivity issue rather than a daemon log format regression. The linuxptp-daemon does emit this log line (printNodeProfile in pkg/daemon/daemon.go:1369 writes the rendered Ptp4lConf with #profile: prefix and message_tag), but the HTTP connection carrying the pod log stream is dropped before the data reaches the test. The progressive Unauthorized failures at job end suggest the kubeconfig token was near expiry, which may also have disrupted API server proxy connections to node kubelets mid-run.
