Root Cause Groups


• 34/36 failures — T-GM ts2phc FREERUN cascading to all downstream suites (suites: bc, dualfollower, dualnicbc, dualnicbcha, tgm)

k8snetworkplumbingwg/linuxptp-daemon PR #629 (commit 14eb788, "Sync from upstream 22-Jul-2026", merged 2026-07-22) introduced addons/intel/e825.go, whose setupGnss() (line 262) fails to locate or enable GNSS pins on node cnfdf32, so ts2phc never receives a 1PPS signal and stays in FREERUN (openshift_ptp_clock_state{process="ts2phc"} 0) despite the hardware DPLL being LOCKED (process="dpll"} 1). With no valid T-GM source, both ptp4l.0.config and ptp4l.1.config on the downstream BC node cnfdf30 also stay in FREERUN (clock_class=255, all interfaces in MASTER role, 4 crash/restarts each), phc2sys stays DOWN (status=0), and after ptphelper.RestartPTPDaemon() is called in parallel_suite_test.go:68 the clock cannot re-lock within the parallel event test window, causing every testSyncState() retry (30 × 10 s) at ptp.go:393 to time out across all affected suites.


• 1/36 failures — Event value key-scheme mismatch causes LOCKED state to go undetected (suite: oc)

Commit d20ffcbf (CNF-19588, 2026-07-03, main) changed test/pkg/event/event.go:742-751 to key StoredEventValues by v.Resource (the full resource-address path, e.g. /cluster/node/cnfdf30.../CLOCK_REALTIME) instead of string(v.DataType), but test/conformance/parallel/ptp.go:413-415 still reads values["notification"].(string) and values["metric"].(float64). Both keys are absent from the new map, so wasLocked in testSyncState() is never set to true, and the test always times out despite the daemon correctly reporting a LOCKED state in the raw CloudEvent payload.


• 1/36 failures — T-BC topology solver finds no valid hardware (suite: tbc)

PR #205 (aede1e93, merged 2026-06-23, main) added T-BC topology tests and the five-constraint solver in testconfig.go:704-710 (WPC NIC receiver, two same-NIC transmitters, WPC NIC local GM on same LAN). The lab cluster (cnfdf30/31/32) has WPC hardware sufficient for TGM tests but not the multi-port T-BC topology. Rather than calling Skip(), execute.BeforeAll at ptp.go:363-368 calls Fail() when CreatePtpConfigurationsWithRetry(3) returns "no T-BC solution found for TBC", surfacing as a hard failure instead of a lab-capability skip.

• Root Cause: After RestartPTPDaemon() in parallel_suite_test.go SynchronizedBeforeSuite, the cloud-event-proxy sidecar on the BC clock-under-test node (cnfdf32) is not yet serving valid responses (HTTP 200) to the consumer app's getCurrentState polling. The serial suite's event tests pass because they run before RestartPTPDaemon().
