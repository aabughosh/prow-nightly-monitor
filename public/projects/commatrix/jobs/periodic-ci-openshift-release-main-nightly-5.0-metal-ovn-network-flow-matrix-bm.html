TL;DR: Six crio ephemeral TCP ports have no EndpointSlice because the Linux dynamic-range filter was removed, failing the matrix-vs-ss validation test.


Root Cause Groups:


• Group 1: crio ephemeral ports — no EndpointSlice filter (affects Tests: Validation [It] should validate the communication matrix ports match the node's open ports)
• Evidence:

```

[FAILED] the following ports are used but don't have an endpointslice:

Ingress,TCP,36231,,crio,,,master,false

Ingress,TCP,37273,,crio,,,master,false

Ingress,TCP,38679,,crio,,,master,false

Ingress,TCP,34333,,crio,,,worker,false

Ingress,TCP,39625,,crio,,,worker,false

Ingress,TCP,42251,,crio,,,worker,false

In [It] at: /tmp/secret/commatrix/test/e2e/validation_test.go:161

```

Raw ss confirms each is crio on a node-specific ephemeral port (32768–60999 Linux range), e.g.:

```

LISTEN 0 4096 192.168.111.21:36231 0.0.0.0:* users:(("crio",pid=4446,fd=11))

```

• Root Cause: crio opens one ephemeral TCP port per node (health/gRPC endpoint, 32768–60999 range) with no Kubernetes EndpointSlice. Previously these ports were silently excluded because the generated commatrix included the Linux dynamic range, causing filterOutPortsInDynamicRanges (validation_test.go:159) to drop them. Commit 7d56343 ("Remove Linux Dynamic ranges from generated communication matrix") removed those ranges from commatrix.DynamicRanges, so the filter now passes crio ports through. filterOutPortsOfKnownServices (validation_test.go:157) only skips rpc.statd, dnsmasq, and dig — not crio — so all 6 ports reach the Fail() at line 161.
• Breaking PR/Commit: Commit 7d56343 / PR #400 ("Remove Linux Dynamic ranges from generated communication matrix"). Branch-awareness note: the build log confirms the job cloned and ran from release-5.0 (Switched to a new branch 'release-5.0'), so this change is present on the production branch.
• Is it a flake? No — crio always opens exactly one ephemeral port per node; the dynamic-range removal makes this a deterministic failure on every run.
• Suggested Fix: Add crio to the filterOutPortsOfKnownServices allowlist in validation_test.go, or introduce a separate "exclude-from-endpointslice-check" dynamic range distinct from the firewall range so crio ephemeral ports are skipped without re-opening the broad Linux range for firewall purposes.
• Affected tests: Validation [It] should validate the communication matrix ports match the node's open ports (validation_test.go:141–163)

• Group 2: Stale documented matrix entries (generates warnings; not the direct FAIL trigger)

• Root Cause: 10 ports in docs/stable/raw/bm.csv no longer exist on OCP 5.0 nodes: metal3 ports 6180/6183/6385/6388 are absent (metal3-httpd configuration changed), machine-config-daemon port 8798 moved to loopback-only (ss shows 127.0.0.1:8797), machine-approver kube-rbac-proxy port 9192 was dropped, cloud-controller-manager 9443 no longer open, and NetworkManager UDP 68 is not showing in ss. These are component-side changes in OCP 5.0 not yet reflected in the matrix docs.
• Breaking PR/Commit: Unknown (upstream OCP component changes in 5.0, not in commatrix repo).
• Is it a flake? No — these ports are consistently absent from ss output; the cluster configuration changed.
• Suggested Fix: Remove the 10 stale entries from docs/stable/raw/bm.csv (and any derived unique/platform-specific CSVs). Confirm with the respective OCP component teams (machine-api/metal3, MCO, cluster-machine-approver, cloud-controller-manager) that the port removals are intentional for 5.0.
• Affected tests: Validation generated communication matrix should be equal to documented communication matrix (warning only, passed) and Validation [It] should validate the communication matrix ports match the node's open ports (warning only for this group; the FAIL is Group 1).
