• Flake? No — CRI-O consistently opens these ephemeral ports across all nodes every run
• Fix: Either suppress CRI-O and rpc.statd ephemeral ports from matrix validation (filter by port range or process name), or update the documented matrix to mark them as optional/expected. A process-name exclusion list in the commatrix tool on release-4.23 branch is the correct fix.
