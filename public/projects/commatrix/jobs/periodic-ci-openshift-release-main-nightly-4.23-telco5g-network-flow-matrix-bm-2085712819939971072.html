Group A — Crio ephemeral ports not filtered by EndpointSlice check (1 test)

• Tests: Validation [It] should validate the communication matrix ports match the node's open ports

Ingress,TCP,35091,,crio,,,worker,false Ingress,TCP,40973,,crio,,,worker,false Ingress,TCP,42821,,crio,,,worker,false

• Root Cause: Crio binds one ephemeral TCP port per node on the node's primary IP for its gRPC streaming server (confirmed in raw-ss-tcp: 192.168.17.196:43499, 192.168.17.195:45999, etc.). These have no EndpointSlice. The test at validation_test.go:159 calls filterOutPortsInDynamicRanges(missingEPSMat, commatrix.DynamicRanges), but commatrix.DynamicRanges only covers the NodePort range 30000–32767 (KubeletNodePortDefaultDynamicRange). PR #400 (merged main Apr 28 2026, commit 1fec55d) removed the Linux ephemeral range (32768–60999) from DynamicRanges — eliminating the filter that previously suppressed these crio ports. The 6 failing ports (35091–45999) are all in the ephemeral range but above NodePort max 32767, so they are never filtered. Backport to release-4.23 is unverified (check_backport.py unavailable).
• Breaking PR/Commit: Candidate (unverified): [PR #400](https://github.com/openshift-kni/commatrix/pull/400) — commit 1fec55d on main, which changed pkg/dynamic-ranges/dynamic-ranges.go (-114 lines) and test/e2e/validation_test.go (-1 line). Must verify whether cherry-picked to release-4.23.
• Flake? No — crio consistently binds one streaming port per node (observed on all 5 nodes: cnfdu17, cnfdu17-master-1, cnfdu17-master-2, cnfdu17-worker-0, cnfdu17-worker-1).
• Fix: Add "crio" to filterOutPortsOfKnownServices in validation_test.go:221 (analogous to the existing "rpc.statd" exclusion), or add the Linux ephemeral range to the EndpointSlice check's filter specifically. This filter lives on main/release-4.23 test code, not in production images.
