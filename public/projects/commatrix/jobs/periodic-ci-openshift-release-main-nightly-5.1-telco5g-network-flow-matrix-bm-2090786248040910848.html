• Root Cause: CRI-O binds ephemeral/random high ports on node IPs (e.g., 34703, 36755, 44001 on masters; 33167, 45875, 46427 on workers) that are detected by ss as open. These ports have no backing EndpointSlice because they are CRI-O internal sockets (stream server, metrics, etc.), not Kubernetes services. The test at validation_test.go:161 treats any port open on a node IP without an EndpointSlice as a failure.
• Breaking PR/Commit: Unknown — this is a runtime behavior of CRI-O assigning non-deterministic ephemeral ports; not tied to a specific commit.
• Flake? yes — CRI-O port numbers are ephemeral and change each run; the matrix-diff-ss file confirms these appear as - (in ss but not matrix), and they are consistently crio-owned with no fixed port. The doc-diff-commatrix shows no CRI-O ports documented, confirming this is a recurring pattern.
• Fix: The test or the commatrix tool should filter out CRI-O internal ephemeral ports (those bound to a node IP without a corresponding EndpointSlice and owned by crio) either by process-name exclusion or by treating ports in the ephemeral range (>32767) opened by crio as non-violations. Alternatively, add an exception for known CRI-O stream server ports in the matrix with Optional: true.
