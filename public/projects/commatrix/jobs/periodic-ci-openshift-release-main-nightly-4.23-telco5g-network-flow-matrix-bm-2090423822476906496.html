• Root Cause: CRI-O binds ephemeral/random high TCP ports on the node's external IP for container runtime communication. The port numbers change each run (e.g., 43383, 44533, 35679 on masters; 37189, 42223, 43541 on workers), confirming they are dynamic CRI-O sockets.
• Breaking PR/Commit: Unknown — pre-existing CRI-O behavior; not a recent regression.
• Flake? yes — port numbers differ each run, behavior is inherently non-deterministic.
• Fix: The test or the matrix generator should filter out dynamic CRI-O ephemeral ports (processes named crio on non-standard ports without EndpointSlices) as known-noisy entries, or suppress them from the EndpointSlice validation path.
