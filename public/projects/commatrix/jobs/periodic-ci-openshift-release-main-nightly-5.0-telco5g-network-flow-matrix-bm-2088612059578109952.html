• Root Cause: CRI-O binds ephemeral/dynamic TCP ports on the node's primary IP (not loopback) for internal communication (e.g., streaming/exec channels). These ports are real open ports detected by ss but have no corresponding Kubernetes EndpointSlice, so the test flags them as "used but missing endpointslice." Port numbers vary per run (34875, 37115, 39359, 40051, 42687), confirming ephemeral assignment. The matrix-diff-ss file shows these same ports marked with - (open but undocumented). This is a known transient condition — CRI-O's gRPC streaming ports are dynamically assigned and not registered as EndpointSlices.
• Breaking PR/Commit: Unknown — this is a CRI-O runtime behavior in OCP 5.0, not a code regression in commatrix.
• Flake? yes — port numbers change every run; the condition depends on active CRI-O streaming sessions at test time.
• Fix: Exclude ports owned by crio process from the EndpointSlice validation check (add a process-name allowlist for known ephemeral-port processes like crio and rpc.statd), or filter ports bound only to node-specific IPs (non-wildcard) with no namespace/service context.
