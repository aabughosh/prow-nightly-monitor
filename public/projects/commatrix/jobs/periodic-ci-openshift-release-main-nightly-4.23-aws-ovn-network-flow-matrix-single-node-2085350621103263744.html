• Root Cause: Three distinct sub-causes. (1) OVN-Kubernetes dynamic NodePort assignments TCP 30797, 31019, 32698 for ovnkube-node-dzkf9 pod — these are in the 30000–32767 NodePort range, dynamically allocated per-cluster, and will differ every run. (2) rpc.statd ephemeral RPC ports TCP 34977, 57923, UDP 35068, 36918 — reassigned by the kernel on every boot; PR #400 removed dynamic-range entries from the generated matrix but the validation still flags them because they have no EndpointSlice. (3) CRI-O TCP 45055 — a new metric/API port added in OCP 4.23 (crio pid=2676), absent from the current documentation.
• Breaking PR/Commit: Unknown for (1) and (3) — OCP 4.23 nightly platform changes. For (2), PR #400 (7d56343) removed the entire dynamic port range entries; that fix is on main — if not backported to the SNO CSV, rpc.statd ports will continue appearing.
• Flake? No — same ports consistently open across all ss poll intervals. CRI-O port 45055 is stable (fixed pid=2676).
• Fix: (1) Add OVN-Kubernetes NodePort-range entries to the documented SNO matrix or configure the test to skip dynamic 30000–32767 ports for host-network pods. (2) Ensure the rpc.statd port-range exclusion from PR #400 is applied to the SNO CSV file. (3) Add crio TCP 45055 to the SNO master matrix with Optional=false.
