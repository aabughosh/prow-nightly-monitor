The linuxptp-daemon unconditionally deletes the CounterVec label set in DeleteProcessStatusMetrics (cleanup.go:58), resetting the counter to 1. By the time the test polls, ptp4l is already at class 248.

• Suggested Fix: In testSyncState (and any other consumer of StoredEventValues), replace values["notification"] with a lookup that iterates over the map looking for a value whose key ends in CLOCK_REALTIME (or reconstruct the expected resource path), OR revert the createStoredEvent key strategy for notification values to keep string(v.DataType) as the key and use a qualified key only for METRIC values where collision is the actual concern.
