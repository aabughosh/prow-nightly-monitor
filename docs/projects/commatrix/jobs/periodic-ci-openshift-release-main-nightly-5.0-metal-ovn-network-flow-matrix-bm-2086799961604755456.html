Group A — crio ephemeral ports not suppressed (1 test)

• Tests: Validation [It] should validate the communication matrix ports match the node's open ports
• Classification: test_regression | Confidence: high

Ingress,TCP,41161,,crio,,,master,false

Ingress,TCP,36081,,crio,,,worker,false (+ 4 more crio ephemeral ports)

• Root Cause: crio opens random ephemeral TCP ports (range 32768-60999) on each node; these appear in ss output but have no EndpointSlice backing. filterOutPortsOfKnownServices in validation_test.go:221 suppresses rpc.statd, dnsmasq, and dig but not crio. filterOutPortsInDynamicRanges (validation_test.go:241) could suppress them if commatrix.DynamicRanges covered Linux ephemeral range 32768-60999, but that range was removed from generated commatrix by main-branch commit 1fec55d ("Remove Linux Dynamic ranges"). Whether 1fec55d is backported to release-5.0 (the branch the test runner uses) is unverified — scripts/check_backport.py does not exist in the local clone.
• Breaking PR/Commit: Candidate (unverified): commit 1fec55d / [PR #400](https://github.com/openshift-kni/commatrix/pull/400) "Remove Linux Dynamic ranges from generated communication matrix" — only confirmed on main; backport to release-5.0 unverified.
• Flake? No — crio always opens these ports, the mismatch is deterministic per run.
• Fix: Add crio to the known-services exclusion list in filterOutPortsOfKnownServices (validation_test.go:221), OR add a new filterOutPortsOfProcess helper that skips ephemeral ports owned by host-level non-k8s processes like crio.
