• Build log: [FAIL] Validation ... validation_test.go:161 → FAIL! -- 3 Passed | 1 Failed
• Root Cause: crio binds TCP 44405 (an ephemeral streaming port, within Linux's default ip_local_port_range 32768–60999) on the SNO node. It has no EndpointSlice backing and is not excluded by filterOutPortsOfKnownServices (which only skips rpc.statd, dnsmasq, dig). This port was silently ignored before commit 7d56343 (PR #400, merged 2026-02-05 on main) because getLinuxDynamicPrivateRange() covered 32768–60999. PR #400 removed that range from GetDynamicRanges() AND removed LinuxDynamicPrivateDefaultDynamicRange from validation_test.go's doc-diff filter. The only remaining dynamic filter is 30000–32767 (Kubelet NodePorts), which does not cover 44405. Since CI runs test scripts from main against release-4.23 cluster images, the stricter test now surfaces this port. The port itself is unchanged in 4.23 — it was always there, just previously filtered.
• Breaking PR/Commit: Candidate: [PR #400 / commit 7d56343](https://github.com/openshift-kni/commatrix/commit/7d56343e0d6e32f2fcc9b639ada47bb83cc57740) — Remove Linux Dynamic ranges — on main only; not verifiable on release-4.23 (no remote branch in local clone).
• Flake? No — crio consistently binds to this port; the missing filter is deterministic.
• Fix: Add "crio" to filterOutPortsOfKnownServices in test/e2e/validation_test.go (treating it like rpc.statd — ephemeral/streaming port with no EPS backing), OR investigate why crio uses an ephemeral port with no EndpointSlice and add proper documentation/EPS for it.
